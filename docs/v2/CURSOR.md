# Hosted Cursor executor and provider fallback

Brokk is the orchestrator. Devin and Cursor receive the same sealed approved scope, task and versioned design contract. The default UI policy is automatic: prefer configured Devin; use hosted Cursor when Devin is absent or definitively refuses creation with HTTP 402/403/429. Explicit Devin/Cursor selections keep their provider. Fallback preserves the same run, request key and context, and records both attempts and the refusal in the project audit. No timeout, 408/409, 5xx or unconfirmed session creation triggers another paid execution. Cursor failures after starting code are never replayed on another provider.

## Worker service

`worker/Dockerfile` is the trusted controller deployed through `docker-compose.worker.yml` as a private Coolify application from this repository after green Woodpecker CI. It exposes only an internal health endpoint; it has no public domain. `worker/runner.Dockerfile` builds the vendor CLI and Node 24 development image. The runner pins the official Cursor release 2026.10.12-d47ca18. Build that image, record its image ID and configure `BROKK_RUNNER_IMAGE` with that immutable ID. Rebuild deliberately when updating the CLI. `worker/egress.sh` and `worker/egress.service` establish the dedicated coder bridge and persistent host firewall before enabling capacity. They only manage their own bridge and chain.

Private server configuration: `BROKK_WORKER_ORIGIN`, `BROKK_CURSOR_WORKER_SECRET`, `BROKK_WORKER_GITHUB_TOKEN`, `CURSOR_API_KEY`, `BROKK_WORKER_REPOSITORY_OWNER`, `BROKK_WORKER_ID`, `BROKK_RUNNER_IMAGE`, `BROKK_RUNNER_NETWORK`, `BROKK_WORKER_ROOT`, `SOURCE_COMMIT`. Use server secrets; never put values in source, browser, logs or job prompts. The Compose definition mounts the trusted controller's persistent root at the same absolute host path and its Docker socket. Compose remains the source of truth for these mounts. The controller is infrastructure software and must remain admin-only; never mount its socket, root, credentials or Git metadata into a coder job.

The controller serializes jobs with a persistent filesystem lock. Presence is renewed every 15 seconds; Brokk considers capacity offline after 60 seconds. Claims are organization/project scoped in the durable queue, authorized by the configured repository owner, immutable preview recipe and approved contract. Protected infrastructure repositories are refused. Each owner has one live job; database row locks prevent duplicate concurrent claims. Jobs renew private leases every 15 seconds. Expired jobs fail visibly and cannot be reclaimed automatically.

## Execution boundary

Each model turn runs as UID 1000 in a disposable container with a read-only root, all capabilities removed, no privilege escalation, 2 CPUs, 3 GiB RAM, 256 PIDs and bounded scratch volumes. Only the current source workspace plus read-only product context and next-turn feedback files are mounted. Large contracts never enter process arguments, avoiding Linux argument-size limits. The outer Docker boundary isolates all tools; nested Cursor sandboxing is disabled to avoid granting kernel capabilities to the container. The dedicated bridge blocks host/private/carrier/metadata networks, management/database ports and all egress except public HTTP/HTTPS/DNS. The only vendor credential passed to the CLI is the Cursor API key. Broker, Git, database and deployment credentials remain in the trusted controller. Repository-provided MCP, hooks and agent config are removed from execution; personal settings are never copied.

The CLI cannot commit, push, merge or deploy. After the container stops, the trusted controller restores Git metadata, checks protected paths, bounds delivery size, scans generated files for its credentials, commits to a run-specific feature branch and opens a PR to `preview`. Changes to infrastructure, CI, env files and execution configuration fail for technical inspection. Woodpecker is the required validation gate on the exact PR head; Brokk's existing review, integration and official preview publication gates remain mandatory. Product approval never authorizes client production promotion.

Only assistant text is published to Brokk, never model reasoning or raw tool output. Operator feedback is consumed on the next turn of the same session (up to four turns). Execution is bounded to 40 minutes and a six-minute no-progress watchdog. A terminal run closes feedback; a later request starts a new approved task. Private receipts retain state, session and Git delivery details. On controller restart, in-flight containers stop and attempts close as failed while preserving the workspace; no model turn, push or ambiguous PR creation repeats automatically.

## Protocol and verification

Server-only endpoints: POST `/api/worker/cursor/presence`, `/claim`, `/:runId/report`, authenticated with the private worker secret and same-origin header. Authenticated operators see capacity through GET `/api/executors` and progress/messages through project-scoped development routes. Cookies alone never authorize worker endpoints; clients cannot initiate execution or send operator messages. Worker owner IDs, leases and resource credentials are not returned to workspace/browser APIs.

Run `python3 -m unittest discover -s worker -p 'test_*.py'` alongside the repository type/lint/test/build checks. Woodpecker performs these boundary tests too. Deployment verification must include internal worker health, public Brokk health, actual hosted execution, fallback audit, operator next-turn feedback, a PR generated by the remote controller and exact-head CI. Authentication ready is not a statement about future vendor quota: subsequent refusals fail visibly. Preserve private workspace receipts for operational recovery; retention and disposal are an administrative operation, never a blind restart cleanup.
